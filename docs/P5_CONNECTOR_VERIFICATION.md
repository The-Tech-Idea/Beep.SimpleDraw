# P5 connected workflow verification
Date: 2026-10-05. Engineering implementation verified by automated tests and desktop Chromium/WASM smoke; independent acceptance remains open.

## Implemented contract
Native envelope v6 retains DiagramDto schema 3 and the existing LineDto. Versions 1–5 keep rejecting connectors. Reviewed connectors join an output port to an input port on distinct exact reviewed workflow types. Up to 4,000 lines; one edge per port. Static cycles are drawable; this application never invokes workflow execution. Three existing routes, bounded supported single-line labels (128 characters), required Kalam outlines at 14 px, fixed 2 px stroke, and 4–32 unit arrows. Colors, endpoint GUIDs, arrows, route and label placements survive native roundtrip. Unreviewed transition/schema/animation/status/ERD metadata, component indices, dangling or occupied endpoints and unsupported live paint properties are rejected before mutation. Routing uses the existing Beep paths; obstacle avoidance is not implemented.

LineDto has no persisted line identity. Copies create new ConnectionLine objects and fresh component/port/group GUIDs, remapping every endpoint. No invented line-ID claim or parallel connector model is made. Library and duplication subsets retain internal edges only. Combined-board validation precedes one atomic insertion batch.

Shared AddLine/RemoveLine, configured ConnectComponents and exact DisconnectComponents settle both ports and component relationships. Connect/disconnect/delete/rewire undo retain the exact line object, style, endpoints and paint position. RefreshPortLayout updates family geometry before a first paint. ConnectionLine fixes label centering, uses the shared glyph outline renderer and exposes path/arrow/ordinary-label bounds to the one existing export renderer. Routed arrows follow endpoint segment/tangent direction.
