# P6 offline notice downloads

Date: 2026-10-06. Task [6.B.3](../plans/enhancements/P6_RELEASE.md). This record concerns delivered file behavior; independent rights/header acceptance remains open.

## Reproduced gap

On the session-overlay release, the actual notices anchor downloaded all 523,698 bytes online. After stopping the owned port-5243 server and confirming zero listeners, the notices page reloaded with all 45 software sections, but the same download anchor produced neither a download event nor a new file. The browser exposed the focused link, and the download observation timed out after ten seconds. Cached page/text access did not prove that the browser's separate download navigation would use its offline cache.

Retained evidence: [online download event](evidence/p6-current-notices-download.json), [actual online file](evidence/p6-current-notices-online.txt), [online page](evidence/p6-current-notices-page.png), [stopped listener](evidence/p6-current-notices-server-stopped.json), [offline page](evidence/p6-current-notices-offline-page.ax.txt) and [missing offline download event](evidence/p6-current-notices-offline-download.json). The failure does not imply unavailable original notices or missing cache integrity; it identifies the download workflow separately.

## Implementation

The existing generated notices page now offers a named download button with a polite status region. The page's small `js/notices.js` module fetches the same aggregate URL through the installed worker and passes its raw bytes to the existing `app.js` `downloadBytes` helper. It preserves BOM, line endings and all original text bytes without decoding/re-encoding. The helper owns the Blob URL, actual link click and delayed URL cleanup, as it already does for editor downloads. Pending retrieval disables repeat activation; missing/network/interrupted reads report a visible failure and permit retry without producing a partial file. The page also provides direct reading of the aggregate and each original text.

All 21 original texts, 45 group metadata records and the full aggregate remain unchanged. The previously generated bundle is preserved under `artifacts/p6-notices-download-old-bundle`; generation still refuses an existing destination. The public `licenses/` inventory remains 24 files. No notice ownership/year/license/signature is inferred or changed.

Packaging now requires exact source bytes and offline manifest integrity for both the notice handler and the shared download helper. Four behavior tests cover exact byte delivery, HTTP refusal/retry, network/body-read failures and repeated activation while pending. A packaging test refuses changed or missing offline handler/helper inputs and checks the named control/status/external-module markup. The focused notice gate passes 12 tests; the complete native gate passes 289 C# + 77 JavaScript checks.
