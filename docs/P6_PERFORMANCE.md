# P6 performance evidence

Date: 2026-10-05. [Master tracker](../plans/enhancements/MASTER_TRACKER.md) · [Specification](../plans/enhancements/specs/SIMPLEDRAW.md) · [Build contract](BUILD_REPRODUCIBILITY.md).

## Method and environment

Measurements use the actual native-linked Release Blazor editor and existing DrawingSession, DrawingManager, history and SKCanvasView. Open the verified static host with `?diagnostics=1`, import a generated native fixture, select its first ungrouped object, close the object list, fit the board, then run the diagnostic button. Normal URLs do not import the diagnostic JavaScript or show the panel. No measurements are transmitted.

The driver performs 140 alternating ArrowRight/ArrowLeft commands through Home.Shortcut: 20 warmup and 120 measured edits. A sample starts immediately before invoking the ordinary editor command and ends on the second animation frame after its actual canvas paint callback. This is a presentation-frame proxy, not a physical GPU presentation timestamp. Autosave and HTML inspector/announcements remain enabled. Each run verifies 140 document revisions, actual ±1 movement, unchanged final geometry, one active selected component and the shared history's retained capacity of 100. Nearest-rank p95 is compared with the 50 ms specification budget. Raw samples and environment are retained in the linked JSON.

Desktop: Windows 11 Home build 26200, AMD Ryzen 7 4800H (8 cores/16 logical), Codex in-app Chromium 154, 1280×720, DPR 1, foreground visible tab, no CPU throttle. All objects fit within the viewport; text in the mixed fixture overlaps adjacent cells and remains rendered. The seven-tool fixture preserves bundled-font bounds rather than inventing text dimensions. `node scripts/performance-fixtures.mjs <absent-output-directory>` creates 100/1,000/2,000-object product fixtures and a separately labelled 5,000-object native refusal fixture, with deterministic IDs and SHA256 inventory.

## Changes and correctness gates

SketchShape retains its existing SKPath and fill/stroke paints until geometry/style changes, and records existing bundled glyph-outline commands in a disposable SKPicture until text/layout/style changes. Position changes invalidate the affected component's resources. Disposal releases native resources. No scene, history, export or model contract is replaced. Seven-kind native pixel comparisons against newly decoded scenes exercise repeated draws, position/style/size/path/roughness/seed/kind/text changes; existing move/undo/redo/style history is also checked.

The original HTML object list performed repeated whole-scene name scans for every row during every edit. ObjectList now computes duplicate-name counts once per displayed-content change, retains component references and skips rendering when only position/style changes. It tracks reference identity as well as IDs so replacing a file with the same IDs still binds the new active components. Selection, names, kind, groups, paint order and language continue to invalidate the list. The retained rows are UI render data; DrawingManager remains the authoritative scene.

The native-linked candidate passed 171 C# and 51 JavaScript checks. Two additional checks compare cached text with the original absolute glyph commands at integer/fractional coordinates and repeated movements; exact PNG bytes match. ## Controlled startup download model

The source-owned `scripts/serve-profiled.mjs` harness delegates to the same verified static host. `ResponseLink` shares one encoded-body reservation clock across all concurrent responses, caps download at 50 decimal Mbps and adds 40 ms before each response. Idle time cannot build burst credit. HEAD sends no body; disconnects cancel waits/streams. Four new Node checks cover invalid profiles, shared reservations, two concurrent real byte-identical downloads and cancellation. Ordinary hosting retains direct streaming and the same scope/MIME/compression/cache/CSP policy.

The [declared profile](evidence/p6-startup-network-profile.json) was applied to `artifacts/p6-network-profile` sequentially on previously unused origins 5226/5227/5228. Each was a fresh navigation, worker start zero, visible Chromium 154 at 1280×720/DPR 1 on the named desktop, with no CPU throttle. The browser's first actual paint with document storage ready uses the existing second-animation-frame startup proxy. These measurements produced:

| Fresh origin | First usable board (ms) | Completed body responses | Encoded body bytes | Startup/body budgets |
|---|---|---|---|---|
| 5226 | 2,962.5 | 232 | 15,215,287 | ≤5,000 ms / ≤25 MiB pass within this model |
| 5227 | 3,133.3 | 232 | 15,215,287 | Pass within this model |
| 5228 | 3,024.6 | 232 | 15,215,287 | Pass within this model |

[Summary and validation](evidence/p6-startup-50mbps-summary.json) references all three raw browser reports and server JSONL captures. Server logs include successful startup and worker-cache responses through capture close, including two 2,539,672-byte Brotli native-WASM downloads per origin. All 232 captured responses complete with body bytes equal to Content-Length; no aborted responses are omitted from these totals. Full body activity spans about 6.35–6.41 seconds, longer than first usable paint because offline population continues. This separates usable startup from completion of caching. All page resource URLs use the measured origin; page performance entries alone omit worker requests. The first board accepted a real keyboard rectangle; [usable-board evidence](evidence/p6-startup-50mbps-1-usable.txt). Warning/error logs were empty for all three observations.

Scope: this is local aggregate encoded-body pacing and per-response delay, not a physical broadband provider or browser throttling. It excludes DNS/TLS, HTTP header bytes, upload, packet loss, and the refused favicon error response. Fresh origins isolate origin HTTP/worker/storage state, while the already-running browser/OS may retain engine/compilation/file caches. It does not establish a newly launched process's cold compilation or public-host/device performance. The controlled desktop startup scenario is verified; physical-provider/public-host and independent acceptance remain explicit.
